6. ROUTE RECOMMENDATION ENGINE
==================================================

This is the most important part of the project.

Do NOT simply sort routes randomly.

Create a real route scoring algorithm.

Every route should have:

- Total duration
- Number of transfers
- Walking duration
- Waiting duration if available
- Number of transit legs
- Route reliability if available
- Transport modes

Create a configurable scoring function.

Default balanced score:

score =
  normalizedTravelTime * 0.60
  +
  normalizedTransfers * 0.25
  +
  normalizedWalkingTime * 0.10
  +
  normalizedWaitingTime * 0.05

Lower cost should mean a better route.

The exact implementation can normalize values before calculating the score.

Support these user preferences:

1. FASTEST
   Prioritize minimum total travel time.

2. FEWEST_TRANSFERS
   Strongly penalize transfers.

3. BALANCED
   Balance time and transfers.

4. LEAST_WALKING
   Minimize walking.

The recommendation engine should be isolated in its own service/module so it can be tested independently.

==================================================
7. TRANSFER LOGIC
==================================================

A transfer means changing from one transit service/line to another.

Examples:

Bus → Bus on same line:
0 transfers

Bus Route A → Bus Route B:
1 transfer

Metro → Bus:
1 transfer

Metro Line A → Metro Line B:
1 transfer

Walking between nearby stops should NOT automatically count as a transit transfer unless the user changes transport service.

Make the transfer calculation deterministic.

9. ROUTING ENGINE
==================================================

Create a backend service that can construct possible transit journeys.

The engine should consider:

- Origin proximity to stops
- Destination proximity to stops
- Transit lines
- Stop sequence
- Departure times
- Arrival times
- Transfers
- Walking connections

Generate multiple candidate journeys rather than only one.

Then pass those candidates into the recommendation/scoring engine.

Avoid brute-force combinations that could become extremely slow.

Use reasonable limits such as:

MAX_TRANSFERS = 3

MAX_CANDIDATE_ROUTES = 20

MAX_WALKING_DISTANCE = configurable
